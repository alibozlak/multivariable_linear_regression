# Multivariable Linear Regression

Rust implementation of a multivariable linear regression fitted with plain gradient
descent. The partial derivatives it is built on are written down under [`math/`](math).

## The Model

`f(x) = a0*x0 + a1*x1 + ... + a(n-1)*x(n-1) + b`

The data set is generated by Gemini : the square meters and the room count of a flat
are the inputs, its monthly rental price is the expected output. The cost function `J`
is the mean of the squared errors, and the `a` coefficients and `b` are fitted with
plain gradient descent, **without any feature scaling**. Training starts from all
coefficients at `0`.

The feature count `n` is not written anywhere in the code. It is read from the data
set, so the same functions fit a data set of any width.

## The JSON data set

The data set is read from JSON, and the functions are written for **already cleaned**
data. They report a clear error instead of trying to repair a data set that does not
keep to the conditions below.

```json
{
  "inputs":  [ [55.0, 1.0], [130.0, 4.0], [85.0, 2.0] ],
  "outputs": [ 23000.0, 48500.0, 32000.0 ]
}
```

| Condition | |
| --- | --- |
| `inputs` | An array of samples, must not be empty |
| One row of `inputs` | An array of numbers, the features of one sample |
| Row width | The same for every row. **This width is `n`**, the feature count |
| `outputs` | An array of numbers, the value expected for the row at the same index |
| `outputs` length | Equal to the `inputs` length. **This length is `m`**, the sample count |

Note that `n` and `m` are read from two different places : `n` is the width of one
`inputs` row (`2` in the data set above), while the length of `outputs` is `m` (`3`
above). One set of coefficients covers `n` features, not `m` samples.

## Layout

| Path | Content |
| --- | --- |
| `src/main.rs` | Reads the data set, sets the starting coefficients and starts the training |
| `src/without_feature_scaling.rs` | The model, the cost function, the partial derivatives and the training loop |
| `src/json_data_set.rs` | The JSON deserialization steps |
| `data/gemini_created_data_set.json` | The training data set itself |
| `math/` | The partial derivatives of the cost function |

## Run

```sh
cargo run --release
```

The data set path is relative to the project root, so the program is expected to be
started from there.

One line is printed per gradient descent step and the training loop runs 1,000,000
steps, so writing the output to a file is usually the more comfortable option :

```sh
cargo run --release > train.log
```

Because the features are not scaled, the learning rate has to stay very small
(`0.00003`) to keep the descent stable, and the cost therefore goes down slowly.
